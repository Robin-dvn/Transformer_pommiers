# README - Apple Tree Sequence Modeling Project with Markov Surrogate Modeling

## Introduction

This project focuses on **surrogate modeling of Markov models** using transformer architectures for apple tree development sequences. The main objective is to train decoder-only transformer models to replicate the behavior of Hidden Semi-Markov Models (HSMM) that capture apple tree development patterns.

The workflow consists of:
1. **Base Markov Models**: Hidden Semi-Markov Models that were previously trained on real biological data to capture apple tree development patterns.
2. **Synthetic Data Generation**: Using the trained Markov models to generate large datasets of synthetic sequences for transformer training.
3. **Transformer Surrogate**: Training decoder-only transformers on these synthetic sequences to create neural surrogate models that can replicate Markov model behavior.
4. **Validation**: Comprehensive comparison between Markov-generated and transformer-generated sequences using statistical metrics and likelihood calculations.

The repository provides two methods for sequence generation:
-   **vmapplet method**: Using the original conda package (OpenAlea) for Markov model sequence generation.
-   **HSMM module**: Pure Python implementation for Markov sequence generation and log-probability calculations.

## General Operation

### 1. Markov Model Foundation

The project is built upon Hidden Semi-Markov Models that serve as the reference for surrogate modeling. These models capture the stochastic nature of branch development over time.

-   **Model Parameters**: Stored in TOML files (`data/markov/`) containing:
    -   Initial state probabilities
    -   State transition probabilities
    -   Duration distributions for each state
    -   Parameters are specific to observation types (`SMALL`, `MEDIUM`, `LARGE`) and years (`Y1` to `Y5`)

-   **Sequence Generation Process**: During a given duration in a state, the Hidden Semi-Markov Model generates a sequence of digits corresponding to the type of branch that will develop. The length of the sequence corresponds to the duration spent in that state. The generated digits represent:
    -   `0`: **Dormant** - No active growth
    -   `1`: **Small** - Small lateral branch development
    -   `2`: **Medium** - Medium-sized lateral branch development
    -   `3`: **Large** - Large lateral branch development
    -   `4`: **Floral** - Floral development

### 2. Synthetic Data Generation

Sequences are generated from the trained Markov models to create training datasets for the transformer models.

-   **Sequence Structure**:
    -   Each sequence represents a temporal development pattern of an apple tree branch
    -   Sequences are strings of digits (0-4) corresponding to the state space
    -   Associated metadata includes:
        -   `Observation`: Initial observation type (`SMALL`, `MEDIUM`, `LARGE`)
        -   `Year`: Starting year (`Y1`, `Y2`, `Y3`, `Y4`, `Y5`)
        -   `Terminal Fate`: Final developmental outcome (`SMALL`, `MEDIUM`, `LARGE`, `FLORAL`, `DORMANT`)

-   **Generation Methods**:
    -   **vmapplet method**: Uses the original OpenAlea conda package for sequence generation
    -   **HSMM module**: Pure Python implementation (`utils/HSMM.py`) that reads TOML configurations

-   **Data Format**:
    -   Main dataset: `dataset/markov_python_generated_dataset10000.csv`
    -   Columns: `Observation`, `Year`, `Sequence`, `Terminal Fate`
    -   Example: `MEDIUM,Y4,"12300",DORMANT`

### 3. Transformer Surrogate Training

The `PommierDatasetDecoderOnly` class prepares Markov-generated sequences for training decoder-only transformer models.

-   **Data Preprocessing**:
    -   **Tokenization**: Sequences are broken into individual tokens (digits, observation types, years)
    -   **Vocabulary Construction**: Special tokens added (`<PAD>`, `<SOS>`)
    -   **Sequence Formatting**: Input/target pairs created for autoregressive training
    -   **Batch Processing**: Padding applied for uniform batch sizes

-   **Model Architecture** (`TransformerDecoderOnly`):
    -   Pure decoder-only transformer architecture
    -   Causal attention masking for autoregressive generation
    -   Configurable dimensions: `d_model`, `d_ff`, `n_heads`, `n_layers`
    -   Token embeddings with positional encoding

-   **Training Process**:
    -   Cross-entropy loss on next-token prediction
    -   Adam optimizer with optional learning rate scheduling
    -   Early stopping based on validation loss
    -   Multiple architecture configurations tested systematically

-   **Sequence Generation**:
    -   After training, the transformer model can generate new sequences autoregressively
    -   Generation starts with initial tokens: observation type and year (e.g., `['Y4', 'MEDIUM']`)
    -   The model predicts the next token iteratively until a terminal fate is generated
    -   Generation terminates naturally when the model produces a terminal fate token (`SMALL`, `MEDIUM`, `LARGE`, `FLORAL`, `DORMANT`)
    -   No artificial maximum length truncation is applied - sequences end when biologically meaningful termination occurs

### 4. Comprehensive Validation Framework

Validation is integrated directly into the training pipeline (`pipelines.py`) and provides multiple levels of analysis:

#### 4.1 Statistical Distribution Validation

-   **Sequence Length Analysis**:
    -   Compares average sequence lengths between Markov reference and transformer-generated sequences
    -   Calculates mean and standard deviation of sequence lengths
    -   Provides absolute error metrics between datasets

-   **Sequence Length Distribution Analysis**:
    -   Compares the complete distribution of sequence lengths between datasets
    -   Uses Jensen-Shannon divergence to quantify distribution similarity
    -   Generates histograms with kernel density estimation overlays
    -   Evaluates distributional differences beyond simple summary statistics

-   **State Frequency Analysis**:
    -   Analyzes occurrence frequency of each state (0-4) within sequences
    -   Computes mean occurrence counts and variability measures
    -   Provides absolute error metrics between reference and generated data
    -   Breaks down analysis by observation type and year combinations

-   **Sequential Pattern Analysis**:
    -   Examines "runs" (consecutive identical states) within sequences
    -   Measures: average number of runs per sequence, average run length, run length variability
    -   Identifies pattern preservation capabilities of the transformer surrogate

#### 4.2 Probabilistic Validation (Singularity Environment)

The `singularity_workspace/` provides access to advanced validation using the original OpenAlea package:

-   **Environment Setup**:
    -   Requires Singularity container with OpenAlea package (Python 2.7)
    -   Container includes C libraries for efficient Markov model computation
    -   Image not included in repository due to size constraints

-   **Script Execution Flow**:
    -   `script.sh`: Main script that launches the Singularity container
    -   `singularity_workspace/script.sh`: Script executed inside the container
    -   `singularity_workspace/main.py`: Python validation implementation using OpenAlea
    -   `script_installation_singularity.sh`: Script for installing Singularity on the system

-   **Likelihood Computation**:
    -   **Log-probability calculation**: Evaluates the likelihood of transformer-generated sequences under the original Markov model
    -   **RMSE metrics**: Root Mean Square Error between predicted and actual sequence probabilities
    -   **Forward algorithm**: Efficient computation of sequence probabilities using dynamic programming

-   **Reference Data**:
    -   `singularity_workspace/data/guide/`: HSMC files and statistical baselines for validation

## How to Use

1.  **Prepare the environment**:
    -   Ensure you have Python 3.13+ installed on your system.
    -   This project uses `uv` as a package and virtual environment manager. Install it from [https://github.com/astral-sh/uv](https://github.com/astral-sh/uv).
    -   Synchronize the environment and install dependencies:
    ```bash
    uv sync
    ```

2.  **Dataset preparation**:
    -   The reference Markov dataset is already provided in `dataset/markov_python_generated_dataset10000.csv`.
    -   The `DatasetCreator` class in `utils/DatasetCreator.py` allows generating additional datasets if needed.
    -   The dataset can also be used dynamically with the `DecoderOnlyDynamicPommierDataset` class, which generates sequences on-the-fly during training instead of loading from a static CSV file.

3.  **Configuration options**:
    -   Training configurations are defined in `train_decoder_only.py` with the following key parameters:
        -   `dataset_path`: Path to the CSV dataset file
        -   `seed`: Random seed for reproducibility
        -   `batch_size`: Number of sequences per training batch
        -   `val_split`: Fraction of data used for training (e.g., 0.8 = 80% train, 20% validation)
        -   `vocab_size`: Size of the token vocabulary
        -   `n_head`: Number of attention heads in the transformer
        -   `d_model`: Model embedding dimension
        -   `nb_layers`: Number of transformer decoder layers
        -   `lr`: Learning rate for the optimizer
        -   `nb_epoch`: Maximum number of training epochs
        -   `dim_feedforward`: Dimension of the feedforward network
        -   `dynamic`: Boolean to use dynamic dataset generation
        -   `scheduler`: Learning rate scheduler configuration (currently supports 'None')
        -   `early_stopping`: Early stopping configuration (**Note**: This parameter requires proper configuration as it is not well configured currently)
        -   `continue_training`: Whether to resume training from a checkpoint
        -   `checkpoint_path`: Path to saved model weights for resuming training
        -   `auto_precision`: Automatic mixed precision for faster training
        -   `graph_name`: Experiment name for tracking

4.  **Configure and run transformer training**:
    -   Edit `train_decoder_only.py`:
        -   Set `test = False` for full training, `test = True` for quick testing
        -   Modify `configs` list to specify model architectures
        -   Adjust `nb_epochs` based on computational resources
    -   Execute training:
    ```bash
    uv run train_decoder_only.py
    ```
    -   Results saved in `experiments/` with timestamps and configurations.

5.  **Monitor training progress**:
    -   Training includes integrated validation at each epoch
    -   Statistical validation metrics computed automatically
    -   Optional Weights & Biases logging for experiment tracking
    -   Early stopping prevents overfitting based on validation loss

6.  **Advanced validation with Singularity** (optional):
    -   The advanced validation using RMSE and log-probability calculations is already integrated into the validation pipeline.
    -   The `rmse_and_log_probability_sequence_metric_sequence_analysis` function is responsible for launching this advanced validation.
    -   If you want to avoid managing the Singularity image setup, you can comment out this function call in the validation pipeline.
    -   To enable advanced validation:
        -   Install Singularity using the provided script:
        ```bash
        ./script_installation_singularity.sh
        ```
        -   Ensure the Singularity image is available on your machine or WSL
        -   The validation will automatically run during the training pipeline - no manual execution needed
    -   The system uses `script.sh` to launch the container, which executes `singularity_workspace/script.sh` inside the container, which then runs `main.py` for the actual validation

7.  **Hyperparameter optimization** (optional):
    -   Use Optuna for systematic hyperparameter exploration:
    ```bash
    uv run hyperparameter_optimization.py
    ```
    -   Optimizes model architecture based on validation metrics

## Conclusion

This project establishes a comprehensive framework for creating neural surrogate models of biological Markov processes. By training decoder-only transformers on Markov-generated sequences, we achieve neural alternatives to traditional probabilistic models while maintaining statistical fidelity through rigorous validation.

The integrated validation framework ensures that transformer surrogates preserve the essential characteristics of the original Markov models, including state transition patterns, sequence length distributions, and likelihood properties. The combination of Python-based development with Singularity-based validation provides both accessibility and rigorous evaluation capabilities.

This framework serves as a foundation for advancing neural surrogate modeling in biological systems and demonstrates the potential for transformers to effectively approximate complex stochastic processes while maintaining biological relevance.
